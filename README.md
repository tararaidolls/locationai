# Location AI — прототип скорингу локацій

Вводите адресу і тип бізнесу — отримуєте оцінку 0–100 з розкладом на виміри, сирими метриками,
сильними/слабкими сторонами і «кращими локаціями поруч». Методологія: [`docs/methodology.md`](docs/methodology.md).

Прототип: **Ліон + Вілербан**, профілі **кав'ярня, ресторан, салон краси, зоомагазин**.

## Запуск

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python -m locai build-city lyon          # ~3 хв, один раз: завантажує й готує дані міста
python -m locai score "10 rue de la République" --profile cafe
python -m locai score "25 cours Émile Zola, Villeurbanne" --profile beauty_salon --json out.json
python -m locai score "45.7578, 4.8320" --profile pet_shop
python -m locai score "12 rue Paul Bert" --profile beauty_salon --pdf report.pdf --html report.html

pytest -q
```

Перша оцінка для кожного профілю ще будує еталонний розподіл міста (~5 с, кешується).
Приклади результатів (текст, JSON і PDF) — у [`examples/`](examples/), наприклад
[`paul_bert_beauty_salon.pdf`](examples/paul_bert_beauty_salon.pdf).

## PDF-звіт

`--pdf` друкує звіт через headless Chromium/Chrome (шукається в `PATH`, шлях можна задати
змінною `LOCAI_CHROME`). `--html` зберігає ту саму сторінку як веб-версію звіту.

Три сторінки A4:
1. **Підсумок** — бал, клас A–E, місце в місті, впевненість, ключові цифри, оцінка за вимірами,
   сильні й слабкі сторони.
2. **Карта** (власний SVG, без сторонніх тайлів) — вулиці, пофарбовані за часом пішки (5/10/15 хв),
   густота населення, конкуренти, синергії в зоні, кращі локації поруч; таблиці найближчих
   конкурентів і кращих точок.
3. **Усі метрики** — значення, бал, якість даних, джерело; методика, обмеження, джерела, дисклеймер.

Шаблон: [`locai/templates/report.html`](locai/templates/report.html), логіка: [`locai/pdf_report.py`](locai/pdf_report.py).

## Сайт

```bash
python -m locai serve --port 8000      # http://127.0.0.1:8000
```

Сценарій: адреса + тип бізнесу (з автодоповненням адрес) → **безкоштовне превʼю** (бал, клас,
місце в місті, мешканці й конкуренти в зоні; решта прихована і не передається в браузер) →
**повний звіт** за унікальним посиланням `/report/<token>` (веб-версія + кнопка «Завантажити PDF»).
Звіти кешуються в `data/web/reports/`, замовлення й відгуки — у SQLite `data/web/orders.sqlite`.

### Бета-режим (типово)

Поки `LOCAI_FREE_REPORTS` > 0 (типово 20), оплата вимкнена: перші N повних звітів видаються
безкоштовно за email (з галочкою згоди на контакт). Коли ліміт вичерпано, відвідувачі можуть
залишити email у листі очікування. Під кожним веб-звітом є коротка форма відгуку: корисність 1–5,
чи вплинув звіт на рішення, чи заплатили б за нього, коментар.

```bash
python -m locai beta-stats               # зведення: скільки звітів, відгуки, лист очікування
python -m locai beta-stats --csv export  # + orders.csv, feedback.csv, waitlist.csv
LOCAI_FREE_REPORTS=50 python -m locai serve   # змінити ліміт
LOCAI_FREE_REPORTS=0  python -m locai serve   # платний режим (Stripe або демо-оплата)
```

| Змінна середовища | Призначення |
|---|---|
| `LOCAI_FREE_REPORTS` | кількість безкоштовних звітів у беті (типово 20); `0` вмикає платний режим |
| `STRIPE_SECRET_KEY` | вмикає справжній Stripe Checkout; без неї працює **демо-оплата** (гроші не списуються) |
| `STRIPE_WEBHOOK_SECRET` | секрет вебхука `POST /stripe/webhook` (подія `checkout.session.completed`) |
| `LOCAI_PRICE_CENTS`, `LOCAI_CURRENCY` | ціна звіту (типово 3900 і `eur`) |
| `LOCAI_BASE_URL` | публічна адреса сайту для повернення зі Stripe |
| `LOCAI_CHROME` | шлях до Chromium/Chrome для PDF |

Оплата підтверджується **лише вебхуком Stripe з перевіркою підпису**, а не поверненням користувача
на сайт. Якщо людина повернулась раніше за вебхук, вона бачить сторінку «Підтверджуємо оплату», яка
сама оновиться.

Для запуску в інтернеті потрібні: сервер із Python 3.11+ і Chromium, HTTPS, акаунт Stripe
(ключі + вебхук на `https://<домен>/stripe/webhook`), підготовлені дані міста (`build-city`).

## Як це працює

```
адреса ─► офлайн-геокодер (адреси BAN з Overture)
       ─► прив'язка до найближчого відрізка пішохідної мережі
       ─► Dijkstra: час пішки до кожного закладу і кожної H3-клітинки населення
       ─► сирі метрики з затуханням w(t) = exp(-t/τ)               (locai/metrics.py)
       ─► перцентиль відносно 400 комерційно активних клітинок міста (locai/scoring.py)
       ─► підоцінки → загальний бал → обмеження → клас A–E
       ─► пояснення + пошук кращих клітинок у радіусі 1 км
```

| Модуль | Що робить |
|---|---|
| `locai/sources/overture.py` | Overture Maps напряму з публічного S3 (заклади, дороги, адреси) |
| `locai/sources/population.py` | Meta HRSL (~30 м): населення, жінки, молодь, 60+, діти — агреговано в H3 res 9 |
| `locai/network.py` | пішохідний граф, прив'язка точок до відрізків, edge betweenness |
| `locai/city.py` | збирання й кеш даних міста (`data/<city>/`) |
| `locai/metrics.py` | каталог метрик і їх розрахунок, модель Хаффа |
| `locai/scoring.py` | нормалізація, агрегація, впевненість, «краще поруч» |
| `locai/geocode.py` | геокодер (координати або «номер вулиця[, місто/індекс]») |
| `locai/pdf_report.py`, `locai/templates/` | HTML/PDF-звіт із SVG-картою |
| `locai/service.py` | спільний шар для CLI і сайту: геокодування, оцінка, звіт, автодоповнення |
| `locai/web/` | сайт на FastAPI: сторінки, замовлення (SQLite), оплата (Stripe / демо) |
| `profiles/*.yaml` | профілі бізнесу: зона, сегмент, конкуренти, синергії, ваги, обмеження |
| `profiles/_groups.yaml` | групи закладів через токени таксономії Overture |

Новий тип бізнесу = новий YAML у `profiles/`, код не змінюється.

## Що реалізовано з методології

| Вимір | Метрики | Джерело |
|---|---|---|
| D — попит | D1 населення, D2 цільовий сегмент (зважені) | Meta HRSL |
| W — денне населення | W1 офіси, W2 навчання, W3 готелі | Overture Places |
| A — трафік | A1 транспорт, A2 центральність вулиці, A3 щільність торгівлі | Overture Places / Transportation |
| C — конкуренція | C1 конкуренти, C2 насиченість, C4 модель Хаффа | Overture Places |
| S — синергія | S1 зважені сусіди-синергісти | Overture Places |
| R — ризик | **ще немає** — виключено з балу, знижує впевненість | потрібен SIRENE |

## Відомі обмеження прототипу

- **Доступ до даних.** Середовище, де писався прототип, мало доступ лише до Overture (S3) і Meta HRSL (S3).
  Наступні джерела з методології треба підключити там, де є мережевий доступ:
  INSEE Filosofi (доходи, D3), SIRENE (ризик закриттів R1, робочі місця W1), DVF (оренда),
  GTFS TCL (транспорт A1), BAN API (онлайн-геокодер), Google Places (рейтинги конкурентів C3).
- **A1 транспорт** — слабкий проксі: в Overture майже немає зупинок метро/автобусів (лише лінії трамваю/метро
  та кілька станцій), тому в центрі Ліона A1 буває заниженим. GTFS це виправить.
- **Модель Хаффа** вважає всіх конкурентів однаково привабливими (немає рейтингів) і рахує відстані
  по прямій × 1,3.
- **Лише пішохідна зона**; зона «авто 10 хв» для салону/зоомагазину ще не реалізована.
- **Ваги експертні (v1)**; калібрування моделлю виживання — наступний етап (методологія §7).
- `permanently_closed` в Overture майже порожній (47 із 35 тис. закладів), тому для R він непридатний.
